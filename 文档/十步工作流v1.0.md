# 十步工作流 v1.0 · The 10-step workflow

[返回首页](../README.md) · [English](英文说明v1.0.md)

![准备、调查、重建、边界四个阶段共十个步骤](主图/十步工作流v1.0.png)

核心链条：**可运行的软件 → 调查 → 证据 → 规格 → 代码 → 测试**

<a id="prepare"></a>

## 阶段A 准备 · Prepare

| 步骤 | 做什么 | 要点 |
| --- | --- | --- |
| 1 搞清楚装的是什么 | REA不是新模型，而是编程代理与现成分析工具之间的统一层 | 通过MCP接入，代理像多了一种"感官"；专业工具仍在干重活 |
| 2 安装 | `npx rea-agents@latest setup` | 自动发现代理、展示改动、等你批准；装完重启代理；出问题用 `npx -y rea-agents@latest doctor` |
| 3 知道能看什么 | 能力取决于文件类型和已装工具 | Electron应用最易入门；深度原生分析需要Hopper / Ghidra / IDA之一 |

![你的问题经过编程代理调用REA MCP服务器，再得到证据与重建](主图/工作架构v1.0.png)

<a id="investigate"></a>

## 阶段B 调查 · Investigate

| 步骤 | 做什么 | 要点 |
| --- | --- | --- |
| 4 选一个功能 | ❌"拆解Notion" → ✅"Notion怎样处理粘贴内容" | 先选你真正关心的最小单元，再扩展 |
| 5 写强制给证据的提示词 | 用 [证据优先提示词](../示例/证据优先提示词v1.0.md) | 一个功能；每个结论要证据；写代码前先写规格 |
| 6 跑第一次分析 | `npx -y rea-agents@latest analyze-javascript-application /absolute/path/to/app --json` | 先读结果，只找与目标功能相关的模块 |
| 7 事实与假设分开 | 让代理把发现分成两栏 | 右栏每一条都是问题，不是答案 |

```
已证实 CONFIRMED          假设 HYPOTHESIS
├─ 在代码中找到           ├─ 由命名推断
├─ 运行时观察到           ├─ 由模式假设
└─ 在测试中复现           └─ 尚未验证
```

小块、可验证的证据胜过巨大的报告：REA近期版本专门压缩了证据输出，避免代理被自己的上下文淹没。

<a id="rebuild"></a>

## 阶段C 重建 · Rebuild

| 步骤 | 做什么 | 要点 |
| --- | --- | --- |
| 8 先写规格再写代码 | 用自然语言写输入、输出、边界情况、出错处理 | 这是净室实现的法律与技术基础，也是发现"自己还没懂"的最佳时机 |
| 9 对照原程序测试 | 比较可观察行为 | 案例的共同模式：一个具体行为 → 证明 → 重建（见 [能力与案例](能力与案例v1.0.md#cases)） |

<a id="boundaries"></a>

## 阶段D 边界 · Boundaries

| 步骤 | 做什么 | 要点 |
| --- | --- | --- |
| 10 知道工具的极限 | 读 [误解与边界](能力与案例v1.0.md#boundary) | 不恢复源码、不自动克隆；服务端逻辑、加密、外部依赖在本地看不到 |
