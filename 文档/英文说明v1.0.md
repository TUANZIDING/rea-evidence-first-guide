## Why guessing fails

Ask a model how an app works and you get a confident, plausible answer that is often wrong: it recalls patterns from millions of other programs instead of looking at the one in front of it. REA connects coding agents (Claude Code, Codex, Cursor and others) through MCP to analysis tools such as Ghidra, Frida and JADX, so the agent inspects the real software, cites evidence, and verifies any rebuild with tests.

## Quick start

Requires Node.js 22.19+, 24.11+ or 26+, and npm.

```sh
npx rea-agents@latest setup      # finds your agents, shows changes, waits for approval
npx -y rea-agents@latest doctor  # if anything misbehaves
npx -y rea-agents@latest analyze-javascript-application /absolute/path/to/app --json
```

Restart your agent after setup, then paste the [evidence-first prompt](../示例/证据优先提示词v1.0.md) and ask about one feature only.

## The 10 steps

| Phase | Steps | Key actions |
| --- | --- | --- |
| A Prepare | 1–3 | Understand REA is a layer between agent and tools; install with one command; know what file types you can inspect |
| B Investigate | 4–7 | One feature, not one app; a prompt that forces evidence; read results first; separate facts from guesses |
| C Rebuild | 8–9 | Write the behavior spec before code; test against the original's observable behavior |
| D Boundaries | 10 | No source recovery, no automatic cloning; MIT covers REA itself, not the software you analyze |

## Case studies

| Case | Result | Evidence level |
| --- | --- | --- |
| DX-Ball (1996) | Sound-pan function passes 3,205 x86 cases, all 63 compiled bytes reproduced | Official case; one function only |
| Touhou TH04 (PC-98 DOS) | Bullet-ring angle math rebuilt in C++, compared with historical compiler output | Official case |
| Notion clipboard | Renderer → preload → IPC → main process traced | Official case |
| stress.exe (2000) | Rebuilt in ~30 min, macOS and web versions in 2 h | Personal build log, not a benchmark |

## Boundary

Use REA for learning, interoperability, security research, preservation, or software you own or are authorized to examine. Clean-room: understand the behavior, write a spec, implement only from the spec, test. Never copy proprietary code or assets; commercial tools (IDA, Hopper, JEB) must be properly licensed.
