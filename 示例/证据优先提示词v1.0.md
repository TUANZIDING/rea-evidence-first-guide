# 证据优先提示词 v1.0 · Evidence-first prompt

[返回首页](../README.md) · [十步工作流](../文档/十步工作流v1.0.md#investigate)

可直接粘贴给 Claude Code / Codex / Cursor（需已安装 REA）。也可保存为 skill 文件，每次以相同方式运行。
Paste into your coding agent with REA installed, or save it as a skill file.

## English

```
Investigate how [FEATURE, e.g. offline search] works in [APPLICATION].

1. Identify the relevant modules or functions.
2. Trace the execution path.
3. Show evidence for every important conclusion.
4. Separate confirmed facts from hypotheses.
5. Write a behavior specification.
6. Implement an independent equivalent in
   [STACK, e.g. TypeScript and SQLite].
7. Create tests comparing observable behavior.

Do not copy proprietary source code or assets.
Stop if the investigation exceeds the approved scope.
```

## 中文版

```
请调查 [应用名] 中 [具体功能，如“离线搜索”] 是如何实现的。

1. 找出相关的模块或函数。
2. 追踪执行路径。
3. 每个重要结论都要给出证据（函数、字符串、调用关系或运行时观察）。
4. 将“已证实的事实”和“假设”分成两栏列出。
5. 写一份行为规格说明（输入、输出、边界情况、错误处理）。
6. 用 [技术栈，如 TypeScript + SQLite] 独立实现一个等效功能。
7. 编写测试，对比原程序与新实现的可观察行为。

不要复制任何专有源代码或素材。
如果调查超出已批准的范围，立即停止并报告。
```

## 为什么有效 / Why it works

1. **只查一个功能**，而不是整个应用。
2. **每个结论都要证据**，不确定就明确承认。
3. **先写规格再写代码**——从“理解”重建，而不是从“复制”重建（净室实现）。
